## Summary

Implement a configurable policy system for employee CSV import jobs in the Directory Service. The system provides creating, retrieving, updating, and versioning reusable import profiles (`employee_import_profiles`), deterministic 3-tier effective configuration resolution (System Baseline → Tenant Profile → Job Overrides) with enforced system safety quotas, immutable configuration snapshotting (`employee_import_jobs.config_snapshot`), and multi-company scoping via `company_id` on profiles and jobs validated against the synchronized `CompanyProjectionRepository`. The design strictly follows Clean Architecture, multi-tenant and multi-company isolation, optimistic concurrency control via versioning, and decouples configuration validation from the transport layer.

---

## Technical Context

**Language/Version**: Node.js LTS (v20+), TypeScript 5.x (Strict mode enabled: `strict: true`, `noImplicitAny: true`, `strictNullChecks: true`)

**Primary Dependencies**: NestJS 10.x, TypeORM 0.3.x, `class-validator`, `class-transformer`, `@new-hros/libs-core`, `@new-hros/libs-sql`, `@new-hros/libs-apis`

**Storage**: PostgreSQL 16+ (JSONB columns for policy configuration and immutable job snapshots)

**Testing**: Jest, `@nestjs/testing`, Testcontainers (PostgreSQL)

**Target Platform**: Linux server (Dockerized NestJS microservice container)

**Project Type**: RESTful Web Service (part of Enterprise HRMS Polyrepo)

**Performance Goals**: <50ms p95 latency for profile CRUD and configuration resolution under standard load

**Constraints**:
- Strict multi-tenant and multi-company isolation (tenant derived from JWT context; cross-tenant access denied; `companyId` validated against active local company projection).
- System-level profiles (`tenant_code IS NULL` and `company_id IS NULL`) read-only for tenant administrators.
- Optimistic concurrency control via `version` column.
- Non-overridable system safety limits (batch size, timeout bounds, retry ceilings).
- Out-of-scope: CSV file parsing, Kafka worker execution, database employee writes.

**Scale/Scope**: Enterprise multi-tenant deployment supporting hundreds of tenants and reusable import profiles.

## Complexity Tracking

*No constitutional violations or unjustified complexity introduced.*

| Aspect | Architectural Choice | Justification |
|---|---|---|
| Deep Merge | Custom typed deep-merge | Eliminates external merge library dependencies while strictly preventing prototype pollution and attribute leakage. |
| Standalone Validation | `ConfigurationValidator` class | Allows validation reuse in job creation, profile updates, and CLI/worker pipelines independently of NestJS HTTP pipes. |
| Version Locking | `@VersionColumn()` + `expectedVersion` | Protects profile configurations against concurrent overwrite conflicts without distributed locking overhead. |
| Multi-Company Validation | `CompanyProjectionRepository` check | Validates `company_id` against active tenant companies locally without external HTTP calls, preserving bounded context autonomy. |
